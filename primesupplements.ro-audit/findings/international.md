## Score

**30 / 100.** The only international configuration the store has (the "Ungaria" market with a `/ro-hu` web presence) delivers no localisation at all (same Romanian text, same RON currency, Romania-only legal pages) while doubling the crawlable site to 1 151 URLs, showing ex-VAT prices 17.36 % lower on the duplicate tree and contradicting the store's own delivery terms.
The hreflang markup itself is technically valid (full mesh, x-default, correct `ro`/`ro-HU` codes, canonical-aligned), `html lang` and `content-language` are correct, and the unpublished `hu` locale does not leak, which is what keeps the score above the floor.

## What works

- hreflang set is technically well-formed on every page sampled: self-referencing tag present, full return mesh (`x-default` → `/`, `ro` → `/`, `ro-HU` → `/ro-hu/...`), one `x-default`, valid ISO codes (`ro` = Romanian, `HU` = Hungary), all https, hreflang href string equals the canonical on both variants (`$R/parsed/home.json`, `$R/parsed/pages_homepage-ro-hu.json`, `$R/parsed/pages_product.json`, `$S/intl/body_rohu_product.html`).
- Only one implementation method (HTML `<link>` via Shopify `content_for_header`); the sitemaps carry no `xhtml:link` entries, so there is no HTML/sitemap conflict (`grep -c hreflang $R/sitemaps/*.xml` = 0 everywhere).
- `<html lang="ro" dir="ltr">` on both trees (theme.liquid line 12 uses `request.locale.iso_code`), and the `content-language` header is `ro-RO` on `/` and `ro-HU` on `/ro-hu/...` — consistent with the body language.
- The unpublished Hungarian locale does not leak: `https://primesupplements.ro/hu` → HTTP 404 (`$S/intl/hdr_hu.txt`), and `/ro-hu/sitemap.xml` → 404, so there is no third tree.
- No IP/Accept-Language redirects or cloaking: `/` with `Accept-Language: hu-HU` returns the same `ro-RO` page, `Shopify.country = "RO"` (`$S/intl/hdr_root_hu_al.txt`); Pandectes "geolocation" flags are all `false`.
- A Hungary delivery zone with two active Cargus methods exists in the default delivery profile, so if the market is ever launched properly, checkout will not block Hungarian addresses.

## Findings

### INTERNATIONAL-01 — The "Ungaria" market web presence publishes a complete second copy of the site under /ro-hu/ (575 duplicate URLs with identical Romanian content)
- **Severity:** High
- **Evidence:**
  - Admin API (`markets`): `Ungaria` (gid://shopify/Market/97830830455, handle `ungaria`, `enabled: true`, `primary: false`) has `webPresence` gid://shopify/MarketWebPresence/73400189303 with `subfolderSuffix: "hu"`, `defaultLocale: ro`, `alternateLocales: []`, `rootUrls: [{locale: ro, url: https://primesupplements.ro/ro-hu/}]`, `currencySettings: null`. `shopLocales`: `hu` `published: false`; `ro` primary. `shop.enabledPresentmentCurrencies = ["RON"]`.
  - Live sitemap index (`$S/intl/sitemap_index.xml`) lists 13 children: 7 for the root tree and 6 under `/ro-hu/` (`/ro-hu/sitemap_products_1.xml`, `_pages_1`, `_collections_1`, `_blogs_1`, `_articles_1`, `_metaobject_pages_1`). Per child: child7 = 186 URLs (185 products + `/ro-hu`), child8 = 11 pages, child9 = 23 collections, child10 = 1 blog, child11 = 354 articles → **575 `/ro-hu` URLs out of 1 151 (49.96 %)**; the product sitemap duplicates all 185 `<image:loc>` entries too (`$R/sitemaps/child1.xml` 185 vs `child7.xml` 185).
  - Content parity: homepage text after tag-stripping is 3 099 words on both; difflib similarity **0.9856** — every differing segment is a price digit or the selector label `România`→`Ungaria` (`$R/home.html` vs `$R/pages/homepage-ro-hu.html`). Product page `/products/creatina-creapure` vs `/ro-hu/products/creatina-creapure`: 1 651 words on both, similarity **0.9955**, the only diffs are prices (see INTERNATIONAL-02). Same `<title>`, same meta description, same H1/H2s, same images.
  - Both copies are self-canonical (`<link rel="canonical" href="https://primesupplements.ro/ro-hu/products/creatina-creapure">` on the duplicate), so nothing tells Google which one to keep except the hreflang hint, which Google treats as a hint, not a directive.
  - The duplicate tree is fully self-linked: the `/ro-hu` homepage has 168 internal links to `/ro-hu/...` and 0 to root paths; the `/ro-hu` product page 75 vs 0. Once Googlebot enters via the sitemap or an hreflang tag it can crawl all 575 duplicates without ever leaving. The root homepage links to `/ro-hu` only through the hreflang `<link>` (1 occurrence) and the localization `<form method="post">`.
  - Both `https://primesupplements.ro/ro-hu` and `https://primesupplements.ro/ro-hu/` answer HTTP 200 with `content-language: ro-HU` (`$S/intl/hdr_ro-hu.txt`, `hdr_ro-hu_.txt`), 630 865 bytes each.
- **Affected scope:** all 575 indexable URLs (185 products, 23 collections, 11 pages, 1 blog index, 354 articles, homepage) exist twice; crawl surface 1 151 instead of 576 URLs; 185 product images listed twice.
- **What Google will do:** with 98.6-99.6 % identical body text, self-canonicals on both and hreflang pointing `ro` at the root, Google will cluster each pair as duplicates and choose one canonical per pair, almost always the root URL (x-default and `ro` both point there, all internal links from the root tree stay on the root tree). Expect 575 entries under "Duplicate, Google chose different canonical than user" / "Duplicate without user-selected canonical" in GSC. The hreflang annotation for `ro-HU` is then effectively dropped (a non-canonical URL cannot be an hreflang alternate). Net effect: zero gain in Hungary, doubled crawl load on a 630 KB-per-page site with Cloudflare bot challenges (429 after bursts), diluted link signals while Google is still consolidating, and the risk that for some pairs Google picks the `/ro-hu/` version (which shows a 17 % lower price, INTERNATIONAL-02).
- **Recommendation (option a, recommended now):** remove the web presence so the Hungary market stops generating URLs; keep or deactivate the market itself depending on whether Hungarian orders are wanted (see INTERNATIONAL-04).
  1. Shopify Admin → **Settings → Markets → Ungaria** → card **Domains and languages** → **Manage** → remove the `primesupplements.ro/ro-hu` web presence (switch the market to the primary domain without a subfolder, or delete the subfolder entry under the top-level **Settings → Markets → Domains and languages** list). The exact object is `gid://shopify/MarketWebPresence/73400189303`; the equivalent Admin API call is `marketWebPresenceDelete(webPresenceId: "gid://shopify/MarketWebPresence/73400189303")` (documented for the owner; the audit did not execute any mutation). If there is no intention to sell to Hungary at all, instead open the market → `⋯` → **Deactivate market** (`marketUpdate` with status INACTIVE). Deactivating also removes `Ungaria` from `localization.available_countries`, so the Impact theme's country selector disappears automatically (`sections__footer.liquid` line 133: `localization.available_countries.size > 1`); removing only the web presence keeps the selector (see INTERNATIONAL-05) and the ex-VAT price flip (INTERNATIONAL-02).
  2. Shopify does not support wildcard redirects. Generate 575 one-to-one redirects from `$R/sitemaps/all-urls.txt` (`/ro-hu/<path>` → `/<path>`, `/ro-hu` → `/`) as a CSV (`Redirect from,Redirect to`) and import it at **Online Store → Navigation → URL redirects → Import**. This turns any already-indexed or externally linked `/ro-hu/` URL into a 301 instead of a 404 and lets Google consolidate immediately.
  3. Verify after the change: `curl -I https://primesupplements.ro/ro-hu/products/creatina-creapure` → `301` to `/products/creatina-creapure`; `https://primesupplements.ro/sitemap.xml` lists 7 children; `grep hreflang` on `/` returns nothing (Shopify emits hreflang only when alternates exist).
  4. Resubmit `sitemap.xml` in GSC and request indexing of 3-5 key product URLs to speed up re-evaluation.
  - **Option b (keep the market, no subfolder):** same step 1 without deactivating. The country switch then works on the same URLs via the `localization` form + cookie (no duplicate URLs, no hreflang). Trade-off: Googlebot always sees the Romanian context, Hungarian visitors are still served Romanian text with RON prices, and the ex-VAT price flip (INTERNATIONAL-02) still happens for anyone who selects Ungaria — so fix the tax setting as well.
  - **Option c (do it properly)** is described under INTERNATIONAL-10; it should be a separate, deliberately resourced project, not a reason to keep the current duplicate online.
- **Falsifiability:** if this finding is wrong, GSC Page indexing would show `/ro-hu/` URLs as "Indexed" with their own impressions in the Performance report filtered by page contains `/ro-hu/` and country = Hungary. Expected instead: after the fix, "Duplicate, Google chose different canonical than user" for `/ro-hu/` drops to 0 within 4-8 weeks and `site:primesupplements.ro/ro-hu` returns no results.
- **Leading indicator:** sitemap index child count 13 → 7; `Shopify.country` never `"HU"` in page source; crawl-stats "total crawl requests" per day drops by roughly half for HTML within 2-4 weeks.
- **Effort:** S (15 minutes in Admin + one CSV import)
- **Confidence:** 0.95

### INTERNATIONAL-02 — The /ro-hu/ alternates show different prices for the same products (ex-VAT, exactly ÷1.21) in the same currency, including in the Product JSON-LD
- **Severity:** High
- **Evidence:**
  - Product `/products/creatina-creapure`: root page shows `Preț redus 180,00 lei`, product JSON `"price":18000`, JSON-LD `lowPrice 100,00 / highPrice 180,00 RON` (`$R/pages/product-creatina-creapure.html`). The hreflang alternate `/ro-hu/products/creatina-creapure` shows `Preț redus 148,76 lei`, `"price":14876`, JSON-LD `lowPrice 82,64 / highPrice 148,76 RON` (`$S/intl/body_rohu_product.html`). 180 / 148.76 = **1.2100** = Romania's standard VAT rate (21 %).
  - Same on the homepage product cards: `"price":20000` (root) vs `"price":16529` (`/ro-hu`); text diffs `360,00 → 297,52`, `200,00 → 165,29`, `100,00 → 82,64` (all ÷1.21). All 77 displayed `lei` prices on the homepage are lower on `/ro-hu` by the same factor (71 × 1.210, 5 × 1.211, 1 × 1.208 — rounding), while the ten `300 RON` free-shipping-threshold strings and every word of copy are identical.
  - Root cause: `shop.taxesIncluded = true` (Admin API) combined with Shopify's "Include or exclude tax based on your customer's country" behaviour and no tax registration for Hungary → the HU market strips the 21 % Romanian VAT and presents the net price, still labelled RON/lei. `currencySettings` for Ungaria is `null`, so there is no HUF, just a cheaper RON.
  - The custom snippet `snippets/schema-product-enhanced.liquid` emits the same entity id on both pages (`"@id": "https://primesupplements.ro/products/creatina-creapure#product"`, `"url": "https://primesupplements.ro/products/creatina-creapure"`) with two different `AggregateOffer` price ranges — one entity, two contradictory offers.
  - Free-shipping copy is unchanged on the duplicate ("Livrare GRATUITĂ pentru comenzile ce depășesc 300 RON", `gratuit` 10/10 occurrences on both homepages), so the threshold is announced gross while prices are net.
- **Affected scope:** all 185 products (plus collection cards, homepage cards, search results) under `/ro-hu/`; every price in page text, product JSON, and JSON-LD.
- **Why it matters for SEO:** (1) if Google selects the `/ro-hu/` URL as canonical for any product (same content, both self-canonical), the indexed price, the merchant-listing price and any Merchant Center landing-page check will see 148,76 instead of 180,00 → "price mismatch" disapprovals and a consumer landing on a page whose checkout re-adds 21 % once a Romanian address is entered; (2) contradictory offers for one `@id` reduce trust in the structured data that this site already emits with other defects (see the technical/schema findings); (3) a Romanian consumer who clicks "Ungaria" in the selector sees prices without VAT, which conflicts with the requirement that prices shown to consumers be final prices including VAT (Romanian price-indication rules for consumers require the displayed price to be the final price including VAT — cf. OG 99/2000; flagged for legal review, not a legal opinion).
- **Recommendation:** removing the web presence (INTERNATIONAL-01) removes the duplicate URLs, but the net-price flip survives for anyone who selects Ungaria in the selector as long as the market stays active. Either deactivate the market, or in **Settings → Taxes and duties** untick **"Include or exclude tax based on your customer's country"** (keep "Include tax in prices" on) so every market sees the same gross RON price; or register a Hungarian/OSS tax rate under Taxes and duties → European Union so HU prices stay gross. Re-check with `curl -sS -A "<UA>" https://primesupplements.ro/ro-hu/products/creatina-creapure | grep -o '"price":[0-9]*' | head -1` → must be `18000` (or the URL must 301).
- **Falsifiability:** this finding is wrong if `/ro-hu/products/creatina-creapure` shows `"price":18000`; it is confirmed by the captured 14876. After the fix, Merchant Center → Products → "Price mismatch" issues for any landing page containing `/ro-hu/` must be 0 and URL Inspection of a `/ro-hu/` product must show "URL is not on Google" or a redirect.
- **Leading indicator:** `Shopify.country === "HU"` pages no longer exist, or product JSON price on `/ro-hu/` equals root price.
- **Effort:** S
- **Confidence:** 0.92

### INTERNATIONAL-03 — The hreflang set is technically valid but semantically unjustified: `ro-HU` targets Romanian speakers in Hungary with zero localisation, while the realistic second audience (Hungarian speakers in Romania, `hu-RO`) is not served at all
- **Severity:** Medium
- **Evidence:**
  - Every page emits exactly three tags, e.g. on `/`: `x-default → https://primesupplements.ro/`, `ro → https://primesupplements.ro/`, `ro-HU → https://primesupplements.ro/ro-hu` (`$R/home.html`); the `/ro-hu` copy emits the identical set (full return mesh). Codes are valid (`ro` ISO 639-1, `HU` ISO 3166-1 alpha-2), so Google will *accept* the annotation.
  - `ro-HU` literally means "Romanian-language page for users in Hungary". The page offers Romanian text (identical to the root), RON currency (`Shopify.currency = {"active":"RON"}` on both), Romania-only legal pages (INTERNATIONAL-04), no Hungarian UI (`shopLocales.hu.published = false`), no Hungarian prices (`currencySettings: null`). Per the skill's MT-QA table, "multiple hreflang alternates point to URLs whose content is identical except for header chrome" is the strongest signal of a template-wrapped, untranslated alternate.
  - Market size: the Romanian-speaking minority in Hungary is in the tens of thousands (2022 Hungarian census ≈ 0.03 M), whereas Hungarian speakers in Romania number ≈ 1.0 M (2021 Romanian census, 6 % of the population, concentrated in Harghita, Covasna, Mureș, Bihor, Satu Mare, Cluj) — all already inside the store's only delivery territory and VAT regime.
  - No `hu` content exists anywhere: `/hu` → 404; Accept-Language `hu-HU` → Romanian page.
- **Affected scope:** 1 151 URLs carry three hreflang `<link>` tags each (3 453 tags) for no targeting benefit; the actual Hungarian-speaking demand inside Romania has no landing experience.
- **Recommendation:** short term, let the tags disappear with the web presence (INTERNATIONAL-01). Medium term, if a Hungarian-language audience is wanted, add Hungarian as an **alternate locale of the Romania market** rather than a Hungary market: Settings → Languages → publish `hu` after human-reviewed translation (Translate & Adapt app; 185 products, 23 collections, 11 pages, 354 articles, theme strings) → Settings → Markets → Romania → Domains and languages → add Hungarian as alternate language. Shopify then serves `/hu/...` with `hreflang="hu-RO"`, same RON prices, same Romanian VAT, same Cargus shipping and legal pages (which must be translated too). Validate the demand first in GA4: Reports → User → Demographics → Language, share of sessions with `hu`/`hu-ro` (and GSC queries containing Hungarian terms such as "kreatin", "fehérje por"). Do not publish machine translation without a native review: Google's spam policy treats unreviewed translated pages at scale as scaled content abuse.
- **Falsifiability:** if `ro-HU` were justified, GSC Performance filtered by Country = Hungary would show meaningful impressions/clicks for `/ro-hu/` URLs; a flat zero (expected) confirms the annotation is dead weight. For the `hu-RO` proposal, GA4 language share `hu` > ~3 % of sessions justifies the investment; < 1 % does not.
- **Leading indicator:** hreflang tags count per page 3 → 0 (after option a) or `hu-RO` tags present with translated `<title>`/H1 (after the locale launch).
- **Effort:** S (removal) / L (hu-RO launch)
- **Confidence:** 0.85

### INTERNATIONAL-07 — Structured data on every /ro-hu/ page declares the root URL as the entity URL while the page's canonical and og:url declare /ro-hu/

- **Evidence:** `/ro-hu/products/creatina-creapure` (`$S/intl/body_rohu_product.html`): `"@id": "https://primesupplements.ro/products/creatina-creapure#product"`, `"url": "https://primesupplements.ro/products/creatina-creapure"` (×2), breadcrumb `"item": "https://primesupplements.ro"` and `"https://primesupplements.ro/collections/all"`, Organization `"@id": "https://primesupplements.ro/#organization"`; but `<link rel="canonical" href="https://primesupplements.ro/ro-hu/products/creatina-creapure">` and `<meta property="og:url" content="https://primesupplements.ro/ro-hu/products/creatina-creapure">`. The custom snippets (`snippets__schema-product-enhanced.liquid`, `snippets__schema-breadcrumb-enhanced.liquid`) build URLs from `shop.url`, which ignores the market subfolder, whereas Shopify's `canonical_url` includes it. - **Falsifiability:** on any `/ro-hu/` page, `"url"` inside the Product block equals the canonical href. Today it does not.
- **Leading indicator:** count of `/ro-hu/` pages with `"@id": "https://primesupplements.ro/products/…#product"`.
- **Effort:** S
- **Confidence:** 0.9

### INTERNATIONAL-08 — Canonical and hreflang/sitemap disagree on percent-encoding case for URLs with diacritic handles (canonical lowercase `%c8%9b`, hreflang and sitemap uppercase `%C8%9B`)
- **Severity:** Low
- **Evidence:** `$R/pages/article.html`: `<link rel="canonical" href="https://primesupplements.ro/blogs/news/bcaa-vs-eaa-diferen%c8%9be-%c8%99i-beneficii-pentru-culturisti-ghid-complet">` vs `<link rel="alternate" hreflang="ro" href="https://primesupplements.ro/blogs/news/bcaa-vs-eaa-diferen%C8%9Be-%C8%99i-…">` (and the same uppercase form for `x-default` and `ro-HU`). Sitemap `<loc>` entries with `%` use uppercase (child5: 2 article URLs, child2: 1 page URL `termeni-și-condiții`, duplicated in child11 and child8). Google normalises hex case (RFC 3986 §2.1), so this is unlikely to break the hreflang cluster, but the skill rule "the canonical URL and hreflang URL must match exactly" is violated on these pages and any string-matching audit tool will flag a self-reference mismatch.
- **Affected scope:** 3 canonical pages (`bcaa-vs-eaa-diferen%C8%9Be-…`, `water-out-tinctura-solu%C8%9Bia-…`, `/pages/termeni-%C8%99i-condi%C8%9Bii`) × 2 trees = 6 URLs.
- **Recommendation:** rename the three handles to ASCII (`bcaa-vs-eaa-diferente-si-beneficii-…`, `water-out-tinctura-solutia-…`, `termeni-si-conditii`) with "Create a URL redirect for the old handle" ticked in Admin; this removes the encoding question entirely and shortens the URLs. (The blog clean-up task already covers handle hygiene; include these three.)
- **Falsifiability:** after renaming, canonical and hreflang hrefs are byte-identical; `grep -c '%' $R/sitemaps/child5.xml` counts only image file names.
- **Leading indicator:** number of `<loc>` entries containing `%` in the page/article sitemaps (today 3).
- **Effort:** S
- **Confidence:** 0.8

## Limitations

- GSC/Merchant Center/GA4 were not accessible; every statement about what Google "will" do is based on Google's documented canonicalisation/hreflang behaviour and on the measured 98.6-99.6 % content identity, not on observed index data.
- Prices on `/ro-hu/` were verified on the homepage (77 displayed prices, all ÷1.21) and one product (`creatina-creapure`); products in the "11% TVA" collection (reduced VAT) were not sampled and would show ÷1.11 instead.
- Only one `/ro-hu/` product page and the `/ro-hu` homepage were fetched live (bot-protection budget); the other 573 duplicates were assessed from the sitemap and from Shopify's deterministic market rendering.
- The Hungarian census figure for Romanian speakers and the 2021 Romanian census figure for Hungarian speakers are cited from memory at order-of-magnitude precision; they support the strategic argument, not a finding.
- No test order was placed; checkout behaviour for Hungarian addresses (rate conversion from HUF, tax lines) is inferred from the delivery-profile and tax settings returned by the Admin API.
